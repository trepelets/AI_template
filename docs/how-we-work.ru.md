# Как мы работаем над {{PROJECT_NAME}}

Памятка. Сюда можно вернуться в любой момент и вспомнить, как организована
работа с Claude. Версия для Claude — `docs/process.md`; если правила меняются,
правим оба файла.

---

## 1. Общая схема

```
            ┌───────────────────────────────┐
            │  GitHub: {{OWNER/REPO}}        │  ← ПАМЯТЬ проекта
            │  код + документы + бэклог      │     (главный источник правды)
            └──────────────▲────────────────┘
                           │ читает в начале / коммитит по «зафиксируй»
        ┌──────────────────┼───────────────────┐
  Master-чат          Чат задачи #1       Чат задачи #7 …
  (организация)
```

- **Репо — это память.** Всё, что должно пережить чат, лежит в репо. История
  чатов — не хранилище.
- **Один чат = одна задача** из бэклога. Начинается с «берём #N» (*take #N*),
  заканчивается «зафиксируй» (*commit the session*). Команды работают на обоих
  языках — шпаргалка в разделе 10.
- **Master-чат** — только про организацию работы над {{PROJECT_NAME}}. Технику в
  нём не делаем.
- **Этот репо главный** (ADR 0001).

## 2. Где что лежит в репо

| Файл / папка | Зачем мне |
|---|---|
| `BACKLOG.md` | **Все задачи** с номерами, статусами и приоритетами |
| `STATUS.md` | Короткий срез: что сейчас, главные риски, журнал изменений |
| `CLAUDE.md` | Карта репо и правила для Claude. Мне читать необязательно |
| `docs/architecture.md` | Как устроен проект |
| `docs/learnings.md` | Грабли, на которые уже наступали |
| `docs/decisions/` | Почему сделано именно так (ADR) |
| `docs/runbooks/` | Пошаговые инструкции |
| `docs/reference/` | Справочники по нашим API |
| `{{code dirs}}` | Код |

## 3. Как начать работу над задачей

1. Открываю `BACKLOG.md` и выбираю номер (или спрашиваю в master-чате, что важнее).
2. Создаю **новый чат в проекте {{PROJECT_NAME}}**.
3. Первое сообщение — с явной просьбой подключить репо (иначе можно упереться в
   проверку разрешений, см. раздел 11):
   > Attach {{OWNER/REPO}}. Take #7. Where we are: …

   или: «Подключи репо {{OWNER/REPO}}. Берём #7. Где мы сейчас: …»
4. Сразу прикладываю то, что есть: логи, вывод команд, файлы, скриншоты.

## 4. Во время работы

- Claude правит код **в репо**. На живые системы применяю я.
- Всплыла новая проблема или идея — «**добавь в бэклог**» (*add to backlog*).
- Большие логи и JSON — фрагментом или файлом, а не целиком в чат.
- Чат стал очень длинным — «зафиксируй» и продолжаю в новом чате с «берём #N».

## 5. Как закончить — «зафиксируй» / *commit the session*

Говорю **«зафиксируй»** (*commit the session* / *wrap up*), и Claude:
1. обновит `BACKLOG.md`: статусы, новые задачи, закрытые уйдут в «Done»;
2. обновит `STATUS.md`: «Сейчас», «Риски», строчку в журнал изменений;
3. запишет принятые решения в `docs/decisions/` (только то, что решил я; его
   неподтверждённые предложения пометит как `proposed`);
4. добавит грабли в `learnings.md`, процедуры в runbooks;
5. проверит изменения на секреты, закоммитит и запушит.

**Правила бэклога:**
- **Задачу не переименовывают под новую работу.** Цель достигнута — задача
  закрывается, остаток получает новый номер («split from #N»).
- **Всё найденное по ходу — отдельные задачи** («found in #N»).
- Расширить задачу можно, только если прошу я — Claude запишет, что было раньше.

**После закрытия задачи** захожу в master-чат: «**глянь, как прошло**»
(*review the last session*). Claude проверит коммит рабочего чата и поправит,
если что-то не так.

## 6. Master-чат

- Здесь: как работаем, что важнее, разбор бэклога, инструменты и skills.
- **Claude в master-чате отвечает за процесс**: проверяет итоги рабочих чатов,
  следит за бэклогом, правит правила, когда что-то не работает.
- Когда master-чат разрастётся — новый со словами:
  > This is the new {{PROJECT_NAME}} master chat. Read `docs/process.md` and `BACKLOG.md`.

## 7. Skills

| Skill | Когда срабатывает | Как попросить явно |
|---|---|---|
| `session-handoff` | «зафиксируй» / *commit the session* / *wrap up* | то же |
| `delegated-research` | Большой поиск в интернете (~8+ запросов) | «поищи через Haiku» / *research it with Haiku* |
| `chat-history-recall` | Вспомнить что-то по многим старым чатам | «покопайся в старых чатах через Haiku» |

Субагент Haiku стоит около 70 тысяч токенов только на запуск — выгоден на
больших объёмах, для пары запросов дороже.

## 8. Секреты

- В репо **никогда**: пароли, токены, API-ключи, сырые дампы с сессионными данными.
- Секреты живут в {{credential store}}.
- gitleaks в pre-commit; один раз после клонирования: `pre-commit install`.
- Правки через веб-редактор GitHub обходят pre-commit — там внимательнее.

## 9. Где что настроено

- **Инструкции проекта в claude.ai** — подключить репо, прочитать `CLAUDE.md` и
  `STATUS.md`, «зафиксируй» → `session-handoff`.
- **Доступ Claude к GitHub** — GitHub-приложение Claude; новый репо добавляется
  в его доступы.
- **Skills** — в аккаунте claude.ai, работают во всех проектах.

## 10. Шпаргалка фраз

| По-русски | In English | Что будет |
|---|---|---|
| «Берём #N» | *Take #N* | Claude читает задачу и начинает с неё |
| «Напомни о #N» | *Remind me about #N* / *Brief me on #N* | Справка по задаче без начала работы |
| «Добавь в бэклог: …» | *Add to backlog: …* | Новая задача со следующим номером |
| «Какие задачи сейчас?» | *What's on the backlog?* / *Current tasks* | Сводка по бэклогу |
| «Зафиксируй» | *Commit the session* / *Wrap up* | Бэклог, статус, решения, коммит, пуш |
| «Глянь, как прошло» (master-чат) | *Review the last session* | Проверка коммита рабочего чата |
| «Прочитай CLAUDE.md и STATUS.md» | *Read CLAUDE.md and STATUS.md* | Если Claude не подхватил контекст |
| «Поищи через Haiku» | *Research it with Haiku* | Большой поиск делает субагент |

## 11. Если что-то пошло не так

- **Подключение репо отклонено** (*attach request was denied*) → это проверка
  разрешений, а не GitHub: *"Attach {{OWNER/REPO}} — I approve"* и подтвердить запрос.
- **Claude не видит репо вообще** (*not found / no access*) → проверить доступ
  GitHub-приложения Claude к репо.
- **Claude отвечает без контекста** → «прочитай CLAUDE.md и STATUS.md».
- **Забыли зафиксировать** → в новом чате: «в прошлом чате делали #N, вспомни и
  зафиксируй».
- **Бэклог разъехался с реальностью** → разобрать в master-чате.
