# Формат работы с Claude над проектом — как мы это сделали и как повторить

Шаблон и инструкция по формату работы с Claude над долгоживущим проектом.
Формат сложился на реальном инфраструктурном проекте и проверен на нём. Этот
файл — для владельца проекта; после того как шаблон разложен в новый репо, его
можно удалить или оставить в `docs/`.

---

## 1. Идея в трёх строках

- **Репо на GitHub — это память проекта.** Код, документы, бэклог, решения.
  Всё, что должно пережить чат, лежит там. История чатов — не хранилище.
- **Чаты — рабочие места.** Один чат = одна задача из бэклога. В конце чата
  «зафиксируй» → Claude записывает итоги в репо и коммитит.
- **Master-чат** — один на проект, только про организацию работы. Claude в нём
  отвечает за процесс: проверяет итоги рабочих чатов, держит бэклог в порядке.

```
            ┌───────────────────────────────┐
            │   GitHub: OWNER/REPO (private) │  ← память проекта
            │   код + docs + BACKLOG + STATUS│
            └───────────────▲───────────────┘
                            │ читает в начале / коммитит по «зафиксируй»
         ┌──────────────────┼──────────────────┐
   Master-чат          Чат задачи #3       Чат задачи #7 …
  (организация,        (берём #3 →         (берём #7 →
   «глянь, как          … → зафиксируй)     … → зафиксируй)
    прошло»)
```

## 2. Из чего состоит

| Часть | Где | Зачем |
|---|---|---|
| **Репо** | GitHub, приватный | Единственный источник правды (ADR 0001) |
| `CLAUDE.md` | корень репо | Карта репо + правила для Claude. Claude читает в каждом чате |
| `STATUS.md` | корень репо | Короткий срез: что сейчас, риски, журнал изменений. Читается в каждом чате |
| `BACKLOG.md` | корень репо | Все задачи с постоянными номерами, статусами, приоритетами |
| `docs/process.md` | репо | Правила процесса для Claude (англ.) |
| `docs/how-we-work.ru.md` | репо | Те же правила — памятка для владельца проекта (рус.) |
| `docs/architecture.md`, `learnings.md` | репо | Как устроен проект; грабли |
| `docs/decisions/` | репо | ADR: почему сделано так. Одно решение — один файл |
| `docs/runbooks/`, `docs/reference/` | репо | Пошаговые процедуры; справочники по своим API |
| gitleaks + pre-commit | репо | Секреты не попадают в коммиты |
| **Проект claude.ai** | claude.ai | Инструкции проекта говорят Claude подключить репо в каждом чате |
| **Skills** | аккаунт claude.ai | `session-handoff`, `delegated-research`, `chat-history-recall` — общие для всех проектов, ставятся один раз |
| **Доступ к GitHub** | GitHub-приложение Claude | Без него Claude не видит приватный репо |

## 3. Пошагово: развернуть на новом проекте

### Шаг 0. Подходит ли проекту

Формат окупается, когда проект живёт неделями, работа идёт в нескольких чатах и
есть код или конфиги. Для разового вопроса он не нужен. Для маленького проекта
хватит трёх файлов: `CLAUDE.md`, `STATUS.md`, `BACKLOG.md` — остальное
добавляется по мере надобности.

### Шаг 1. Репо

1. Создать **пустой приватный** репо на GitHub (без README — его зальёт Claude).
2. Дать доступ GitHub-приложению Claude: GitHub → **Settings → Applications →
   Installed GitHub Apps → Claude → Configure → Repository access** → добавить
   новый репо → Save. (Если приложения нет — переподключить GitHub в claude.ai:
   **Settings → Connectors**.)
3. Если в репо попадут внутренние адреса/топология — уточнить у безопасников,
   можно ли их держать на внешнем GitHub.

### Шаг 2. Проект в claude.ai

1. Создать проект (или взять существующий).
2. В **инструкции проекта** вставить текст из `claude-project-instructions.md`,
   подставив `OWNER/REPO` и ключевые факты.
3. Решить, связывать ли память проекта с общей памятью аккаунта (настройка на
   странице проекта). Важно: **поиск по чатам работает только внутри текущего
   проекта** — чаты других проектов отсюда не видны. Поэтому всё общее — в репо.

### Шаг 3. Master-чат и заливка шаблона

Открыть в проекте новый чат, назвать его «🧭 Master — организация работы».
Первое сообщение (с приложенным архивом шаблона):

> Это master-чат проекта <ИМЯ>. Attach OWNER/REPO — I approve.
> Разложи в репо шаблон из архива, заполни заглушки `{{…}}` в `CLAUDE.md`,
> `STATUS.md`, `docs/architecture.md`. Собери знания о проекте из памяти проекта,
> документов проекта и прошлых чатов этого проекта — не жалей токенов, перепроверяй.
> Сведи все известные задачи и проблемы в `BACKLOG.md`. Закоммить и запушь.

⚠ Сбор знаний из истории — **дорогая по токенам операция** (десятки поисков и
чтений). Обычно это оправдано: это фундамент, который потом экономит
каждый следующий чат.

### Шаг 4. Что заполнить руками / проверить

- `CLAUDE.md`: что за проект, карта репо (свои папки с кодом), **«Facts that are
  easy to get wrong»** (версии, имена, «никогда не править X руками»), предпочтения
  по стилю.
- `docs/architecture.md`: компоненты, версии, кто куда ходит.
- `.gitleaks.toml`: добавить правила под свои секреты (например, имена переменных с паролями от оборудования).
- `docs/process.md` и `docs/how-we-work.ru.md`: заменить `{{PROJECT}}`, `{{REPO}}`.

### Шаг 5. Локально, один раз

```bash
git clone git@github.com:OWNER/REPO.git && cd REPO
pipx install pre-commit      # или: pip install --user pre-commit
pre-commit install
pre-commit run --all-files
```

### Шаг 6. Наполнить код

Приложить в master-чат архивы с кодом (`tar czf x.tar.gz dir/`). Claude
разложит их по структуре, выкинет venv/кеши/дампы, проверит на секреты,
сверит со списком того, что нужно, и запишет недостающее в бэклог.
**Сначала вынести секреты** из того, что их содержит (например, экспорты
workflow или конфиги с паролями), и только потом класть в репо.

### Шаг 7. Skills (только для первого проекта)

Skills живут в аккаунте и работают во всех проектах. Если их нет — в любом чате:
«предложи skill session-handoff по файлу `claude-skills/session-handoff/SKILL.md`»
(копии лежат в этом шаблоне) и сохранить из карточки. Так же для двух других.

### Шаг 8. Первая задача

Новый чат в проекте:

> Attach OWNER/REPO. Take #1. Where we are: …

В конце — «зафиксируй», затем в master-чате — «глянь, как прошло».

## 4. Рабочий цикл

```
master-чат: «какие задачи сейчас?» → выбираю #N
      ↓
новый чат: «Attach OWNER/REPO. Take #N. Where we are: …»
      ↓
работа; новые находки → «добавь в бэклог: …»
      ↓
«зафиксируй» → BACKLOG, STATUS, ADR, learnings, runbooks → commit + push
      ↓
master-чат: «глянь, как прошло» → проверка и правки процесса
```

Команды (русский и английский равноценны) — в `docs/how-we-work.ru.md`, раздел 10.

## 5. Чему мы научились (грабли)

| Что случилось | Правило |
|---|---|
| В новом чате подключение репо отклонила проверка разрешений: команда пришла из инструкций проекта, а не от меня | Начинать рабочий чат с явного «Attach OWNER/REPO». Claude при отказе должен остановиться и спросить, а не работать вслепую |
| Субагент Haiku стоит ~70k токенов только на запуск | Делегировать поиск от ~8+ запросов; простое «вспомни» Claude делает сам |
| Рабочий чат «закрыл» задачу, переименовав её под оставшуюся работу | Задачу не переименовывают: цель достигнута → закрыть, остаток → новый номер («split from #N») |
| Находки складывались строчкой «also look at» внутри задачи | Всё найденное — сразу отдельные задачи («found in #N») |
| Коммит сделан без «зафиксируй» → бэклог отстал от реальности | «Напомни о #N» сверяет бэклог с `git log` и подсвечивает расхождение; master-чат проверяет итоги |
| Правка через веб-редактор GitHub обходит pre-commit и gitleaks | В веб-редакторе следить за секретами; master-чат сканирует репо при проверке |
| Код жил в нескольких местах (внутренний GitLab, локальные папки, файлы проекта) | Один канонический репо (ADR 0001), старые места заморозить |
| Решения Claude и решения пользователя смешивались | В ADR указывать, кто решил; предложения Claude без подтверждения — `Status: proposed` |
| Master-чат быстро разрастается и дорожает | Правила — в `docs/process.md`; master-чат пересоздаётся одной фразой |
| Чаты одного проекта не видят чаты другого | Всё, что нужно между чатами, — в репо, а не в истории |
| Длинный рабочий чат дорогой: каждое сообщение перечитывает всю историю | «Зафиксируй» и новый чат с «take #N» |

## 6. Что адаптировать под проект

- **Язык документов.** По умолчанию: документы для Claude — по-английски,
  памятка для владельца — по-русски, общение — на языке разговора.
- **Секреты.** Правила gitleaks под свои типы секретов.
- **Где применяются изменения.** По умолчанию Claude правит код в репо, а на живые
  системы изменения применяет владелец. Это записано в `docs/process.md` → During
  the session.
- **Глубина документации.** ADR, runbooks и reference заводятся по мере
  появления решений и процедур, не заранее.
